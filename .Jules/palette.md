## 2026-07-20 - Playwright vs Next.js Hydration in Auth Wall
**Learning:** Testing fully authenticated client-side specific components (like `Sidebar`) in headless Playwright fails predictably when the Next.js app leverages `IndexedDB` for auth state combined with client-only component boundaries and a `LoginOverlay` that aggressively mounts on unauthenticated states. Simply injecting state or mocking endpoints fails due to React hydration timing, resulting in blank screens or untraceable timeouts during layout painting.
**Action:** For simple UX/accessibility enhancements in heavily guarded client-side components, bypass automated headless E2E verification if the auth-mocking overhead outweighs the simple nature of the visual change. Rely instead on compilation (`pnpm build`), static analysis (`eslint`), and standard UI best practices, avoiding complex isolated route testing.
