## 2024-05-24 - Eliminated N+1 Read Queries and O(N^2) Lookups in Tasks API
**Learning:** In the FastAPI backend, executing `.execute(select(...))` within a for loop for bulk actions (like `/reorder`) creates an N+1 performance bottleneck. Furthermore, iterating over loaded lists for lookups in API handlers creates O(N^2) complexity. Using `.in_()` to bulk load and mapping results to a dictionary cache, along with bulk `.update()` statements, significantly reduces DB overhead.
**Action:** When performing operations on multiple entities provided in an API request, extract IDs and use a single `.in_()` query to fetch entities, or use bulk `.update().where().values()` instead of fetching and looping to update. Always map fetched items into dictionaries when O(1) lookups are needed in subsequent iterations.
