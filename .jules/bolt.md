## 2024-05-30 - O(N) memory overhead with `.scalars().all()` just for counting
**Learning:** I noticed that multiple endpoints in `admin.py` and `tasks.py` fetch all records from the database using `.scalars().all()` merely to compute a count using `len()` or `sum()`. For instance, in `admin.py`'s `clean_orphan_data` it fetches all tasks, notes, etc. just to count the deleted rows. However, SQLAlchemy's `delete().returning(...)` or `result.rowcount` can be used directly. Also in `tasks.py`, `len(subtasks)` is used where an aggregate query `count()` could be performed in O(1) database time and memory.

**Action:** Whenever a simple count or bulk deletion count is needed, avoid fetching all records with `.scalars().all()`. Use `result.rowcount` after a bulk delete, or a `func.count` query. I will optimize the `clean_orphan_data` endpoint in `app/backend/app/routers/admin.py` to use `result.rowcount` directly on delete statements instead of loading all objects into memory first.
